**Deploy** means put a working version somewhere another browser can reach. **Vercel** can build and serve the React page. Its **CLI** is a terminal tool for sending the project and receiving a public URL.

## Publish the page

1. Create or sign in to a [Vercel account](https://vercel.com/signup). Keep login details to yourself.
2. Ask Codex to inspect the actual React project and tell you its build command, output folder, and the setup steps in the <a href="https://vercel.com/docs/projects/deploy-from-cli">current Vercel CLI guide</a>. Follow the steps it confirms for your system.
3. From the Chore Board folder, use the CLI command Codex confirms to create a preview deployment. In the usual Vercel CLI flow, `vercel` starts this action. Read any prompts before accepting their suggested project settings.
4. Wait for the command to finish and copy the URL it prints. Open that URL in a fresh browser tab or another device.

```text
Inspect this Chore Board project for a client-only Vercel deployment.
Tell me the actual build command, output folder, and current CLI setup steps.
Help me publish only the React page. Do not move the server or SQLite yet.
Tell me where the CLI prints the URL and where build errors appear.
```

A successful build means Vercel prepared the page files. It does not mean the chore request works. If the page fails to open, look at the deployment's build logs in the CLI or Vercel dashboard. If the page opens but has no chores, open the browser Network panel and inspect the request address and response.

On **your laptop**, a public page that asks for `localhost` may still reach your running local server. On **someone else's device**, `localhost` points to that device, where your server is absent. Keep that difference in mind when describing what worked.
