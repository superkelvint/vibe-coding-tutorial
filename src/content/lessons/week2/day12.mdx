You can see a fictional chore in Supabase, but the public Chore Board still shows a sample from code. Today the online server will read the hosted table, save a new chore there, and mark one row done. When this works, a chore added through the page will return after refresh and appear in another browser.

```text
browser page → Vercel Function → Supabase chores table
browser page ← answer ← Vercel Function
```

The browser can inspect its own page code. It must never receive the database password. A **connection string** is the private information the server needs to reach the database. Keep it in a server-only setting named `DATABASE_URL`, not in React code or a browser response.

## Connect the existing workflow

In Supabase, open the project's **Connect** information and find the connection option appropriate for a server function. Ask Codex to confirm the <a href="https://supabase.com/docs/guides/database/connecting-to-postgres">current Supabase connection guidance</a> for this project's runtime. Put the real connection value in the local ignored `.env.local` file for local server work and in Vercel's private environment settings for both Preview and Production. Never paste the value into a Codex prompt, project README, or Git commit. A new deployment may be needed after changing an online setting.

Ask Codex to replace the sample answer in three visible steps: load the Supabase row, add a new row, then mark only the selected row done. The existing route shapes should remain compatible with the React page. Have Codex inspect the actual project before editing and run its available project checks when all three steps work.

```text
Connect the existing hosted chore routes to the Supabase chores table.
First make Load return the fictional row already in Supabase. Then make
Add save a row and Done change only the selected row. Keep the browser
calling the Vercel Function, never Supabase directly. Read DATABASE_URL
only in server code; do not print or return its value. Follow Supabase's
current serverless connection and driver guidance for this runtime.
Remove the temporary sample answer from the hosted path. Explain how to
redeploy and where I can see the result. At the end, run available checks
and report pass or fail briefly.
```

Open the new deployment URL. You should see the row from Day 11. Add another fictional chore and refresh: it should return. Mark it done and refresh: only that chore should be done. Open the same URL in a second browser to see the same saved list.

When that Preview result works, ask Codex to confirm this project's production deployment command. In the usual Vercel CLI flow, it is `vercel --prod`. Run it, wait for the production URL, and open that URL. The same fictional chores should load there. Keep the URL for Days 13 and 14.

If the page cannot load chores, look at its Network request first, then the function logs in Vercel. A missing `DATABASE_URL` belongs in Vercel settings; a missing table or column belongs in the Supabase table. Do not copy a secret into browser code to make an error disappear.
