The page is online, but the program that answers chore requests still runs on your laptop. Another person's browser cannot rely on that program. Today you will put a small answering program online and prove the page can reach it. Saved chores remain disconnected until Day 12.

A **Vercel Function** is server code Vercel runs when a browser requests its address. First make a health route that answers `{ "status": "ok" }`. A **route** is an address path such as `/api/health`. Then make `/api/chores` return a clearly labeled sample chore, so you can see the whole page-to-function connection.

## Connect one answer

Ask Codex to inspect the project and current Vercel guidance for its server framework. Keep the health route and sample chore separate from the local SQLite file. Redeploy using the project's established preview command, then open the printed URL. Visit `/api/health` on that host and look for the expected answer. Open the page and look for the sample chore.

```text
Add a Vercel Function for /api/health that answers {"status":"ok"}.
Add a temporary /api/chores answer with one fictional sample chore.
Make the deployed React page ask this same host for chores.
Do not connect SQLite or Supabase yet. Tell me how to deploy and open
both the health URL and page. Report any build failure briefly.
```

If `/api/health` gives 404, check the function path and deployment logs. If the health answer works but the page is empty, inspect the browser Network request to `/api/chores` and its response. If the sample appears, the connection works; the data is still temporary and should not be described as saved.
