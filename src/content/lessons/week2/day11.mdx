The online function can answer with a sample chore, but that sample is written into code. It is not a saved list. Today you will create a place for real chore rows. The app will still show sample data until Day 12 connects it.

**Postgres** is a database program that saves organized rows in tables. **Supabase** hosts a Postgres database for this course. This replaces the job of the SQLite file for the online version; the meaning of one chore stays the same.

## Make the table

1. Ask Codex to inspect the actual SQLite `chores` table. Have it explain the columns in plain words and prepare a small Postgres table definition with the same meaning. A **schema** is the list of table columns and their rules. Save the proposed SQL in the project so the table can be recreated later.
2. Create or sign in to a [Supabase account](https://supabase.com/). Create a project for fictional teaching chores. Keep its database password private.
3. In the project's SQL editor, review the proposed table name and columns, then run the SQL. The editor should report success. Open the table view and confirm the empty `chores` table exists.
4. Add one fictional row, such as “Feed the dog” assigned to “Maya,” using the table view or an SQL insert Codex explains. Find that row again in the table.

```text
Inspect the local SQLite chores table and explain each column.
Prepare one small Postgres SQL file for a Supabase chores table with
matching meaning. Include the rules needed for a valid chore.
Do not connect the app or expose a password. Explain how I can run the SQL
in Supabase and recognize that the table and one fictional row exist.
```

If the SQL editor rejects a command, copy the exact error to Codex and ask what part of the table definition it refers to. If the table exists but the row is missing, check whether the insert completed and whether the table view is filtered.
