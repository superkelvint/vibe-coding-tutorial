Imagine a shopping page where clicking a heart fills it in. The browser can make that visible change immediately. It already has the page and its JavaScript, so it may not need to ask another computer for that one temporary change.

Today you will make a tiny counter page. Each click increases a number you can see. This is **browser state**: information the page holds while it is open. The successful result is a number that changes on click and returns to its starting value after refresh. Saving across refresh comes later.

```text
click → JavaScript changes the number → screen shows the new number
```

Use the page from the preamble or a new `counter.html` file. Ask Codex:

```text
Make a small counter in one HTML file with simple CSS and JavaScript.
Start at 0. Each button click should increase the visible number by 1.
Keep the code beginner-friendly. Tell me which value the browser remembers.
```

Open the file in the browser. Click twice: the number should show 2. Refresh: it should show 0 again. If it never changes, look for a Console error and check whether the button is connected to the JavaScript action. If it changes but does not appear on screen, ask Codex where the displayed number is updated.

A browser can do a great deal locally. It cannot, by itself, make the same temporary number appear on a different person's device. That is the question for Day 3.
