The counter from Day 2 exists only in your browser. Imagine a family chore: one person adds “Feed the dog,” and someone else opens the page on a phone. The second browser cannot read the first browser's temporary memory. Both need a place to ask for the same current list.

A **server** is a program that receives questions from browsers and sends answers. The browser's question is a **request**; the answer is a **response**. The server can later read saved chores and apply shared rules. We will build that server on Day 6. Today you only need to picture the exchange.

```text
Person opens chore page
→ browser asks server for chores
→ server answers with the current list
→ browser shows the list
```

If the answer takes time, the page should show that it is waiting. If the server cannot answer, the page should say the list could not be loaded. A blank page that looks finished would mislead the person.

| What you see | A useful question |
| --- | --- |
| Nothing appears | Did the browser ask? Did an answer arrive? |
| A waiting message remains | Is the server still running? |
| An error appears | What did the server answer? |
| Old chores appear | Did the saved data change, or is the screen stale? |

## Watch a real request

Open a familiar webpage or the standalone <a href={`${import.meta.env.BASE_URL}/lessons/api-basics/`}>APIs example</a>. Open your browser's developer tools and choose **Network**, the list of requests the page makes. Refresh the page and select one request. Look for its address, status, and response. You do not need to decode every field. Notice that the browser asked for something and received an answer or an error.

If the Network list is empty, refresh while the panel is open. If the page uses cached content, try another page or the APIs example.
