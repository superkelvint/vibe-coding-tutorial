On the Chore Board, marking one chore done can affect its row, a Done button, and a summary. If these parts update separately, they can disagree. Today you will use **React** to keep the screen tied to one current list of chores.

A **component** is a named piece of the screen with one job. `ChoreForm` can collect a title and person; `ChoreList` can show the chores; `ChoreItem` can show one row. The app owns the chore list. It passes information to those pieces, and they report actions back. React then redraws the affected screen.

```text
person clicks Done → ChoreItem reports which chore → app changes its list
→ React redraws that row and any summary
```

The behavior stays the same as Day 4. A person can add, assign, and complete chores; blank titles are refused; refresh still clears the list. React does not save or share chores for you.

## Move the board into React

Ask Codex to inspect the Day 4 project, then set up the smallest React project that can show the same board. Use TypeScript for new React files so simple data mistakes can be caught while building. If React or a project script is already present, use it. The <a href={`${import.meta.env.BASE_URL}/lessons/typescript-react-guide/`}>TypeScript for React guide</a> is available when you want the details.

```text
Move the existing Family Chore Board into React with TypeScript.
Keep its behavior and appearance understandable. Use a small form,
list, and item component. Keep one owner for the chore list.
Do not add new product behavior or a database.
Tell me how to start and open the result. Run available project checks
when the rewrite is complete and report pass or fail briefly.
```

Run the development command Codex identifies, usually `npm run dev`, and open the local URL printed in the terminal. If the page is blank, inspect the browser Console and the terminal where the development server is running. A red error in either place is more useful than guessing at a fix.
