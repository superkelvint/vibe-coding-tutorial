Send a message in an app you know. You type, tap Send, and watch for a result. The message may appear immediately, show a waiting symbol, or fail to send. That short moment contains most of the story you will build during this course.

```text
user → data → action → rule → feedback
```

The **user** is the person trying to do something. **Data** is the information the app needs, such as a message and its recipient. The **action** is what the person does. A **rule** decides what is allowed, such as refusing a blank message. **Feedback** is what the person sees while waiting or afterward.

| Familiar action | Data and rule | Feedback |
| --- | --- | --- |
| Send a message | Text, recipient; a recipient is required | Sending, sent, or failed |
| Add an item to a cart | Item, quantity; the item must be available | Cart count changes or an error appears |
| Like a post | Post and like; repeated taps should have a clear meaning | Heart and count change |

The same map helps you locate confusion. If the screen says “sent” but another person never receives the message, you can ask whether the action was received, whether the rule allowed it, whether the data was saved, or whether the screen showed a result too early. You do not need to know the app's private code to ask those questions.

## Try one interaction

Choose one safe action in a familiar app. Before doing it, predict what will appear. Then try it and watch for the moment the screen changes. Avoid sending a real message or placing an order just for this exercise; a cart change or harmless saved item works.
